PART 2.  WHAT TO IMPROVE FOR PRODUCTION
====================================================================

2.1  Security
  [ ] MUST    Change every default password (Admin@123 is on all accounts)
  [ ] MUST    Delete USERS_AND_PASSWORDS.txt
  [ ] MUST    Revoke or rotate every token that was pasted in chat:
                - the GitHub tokens (github.com/settings/tokens)
                - the DuckDNS token (duckdns.org)
                - the Gmail app password
  [ ] MUST    Set ENVIRONMENT=production, COOKIE_SECURE=true, ALLOW_OPEN_ACCOUNT=false
  [ ] MUST    Restrict CORS_ORIGINS to the real address only
  [ ] MUST    Keep secrets out of plain files where possible; never in chat or git
  [ ] SHOULD  Review who holds which permission; force a password change at first login

2.2  Reliability
  [ ] MUST    Run as a service that starts by itself after a reboot and restarts on a crash
              (today the servers are started by hand with start-servers.ps1)
  [ ] MUST    Watchdog + alert to an admin if the worker or mailbox watcher stops
              (it stalled for about 25 minutes on 6 Oct and nobody was told)
  [ ] MUST    Find out why the worker stopped (cause still unknown)
  [ ] MUST    Automatic daily database backups, and test a restore
  [ ] SHOULD  Logs that are kept and searchable; a simple status page

2.3  Where it runs
  [ ] MUST    A proper always-on machine or server (not a slow laptop; not inside OneDrive)
  [ ] MUST    A separate production database (apart from development and test databases)
  [ ] MUST    Real HTTPS on an address that works everywhere: buy a domain (a .co costs about
              Rs 1,500-3,000 a year) and renew the certificate automatically.
              DuckDNS only works on the office network.
  [ ] SHOULD  Fixed IP address; a way to deploy a released version and roll it back

2.4  Email
  [ ] MUST    Use a company mailbox instead of a personal Gmail app password
  [ ] MUST    Give every department account a real email address (only the approver has one)
  [ ] SHOULD  Check sending limits and spam settings for supplier emails

2.5  Quality
  [ ] MUST    A green full browser test run, twice in a row, on the combined code
  [ ] SHOULD  Run the tests automatically on every change and every night
  [ ] SHOULD  Test with real supplier PDFs; check speed with realistic volumes

2.6  Cost and data
  [ ] SHOULD  Daily limit and alert for AI usage (including the new page-image reading)
  [ ] MUST    Load the real suppliers, stock, cost centres and users; clear out all test data
  [ ] LATER   Data retention and privacy review

2.7  Housekeeping
  [ ] SHOULD  Delete the two leftover test databases when finished
              (opetional_agents_test, opetional_agents_basicops_test)
  [ ] SHOULD  Write an admin guide: setup, backup and restore, what to do when it stops
  [ ] LATER   Finance stage, price memory and ratings (Part 1), decision on phone calls
